# Library Channels & HDHR Proxy Expansion

## Overview

Extend Maisie's HDHR emulator to support **library channels** — custom TV channels
that play content from the Plex library on a schedule. A "Golden Girls" channel
plays Golden Girls 24/7; a "Sci-Fi Saturday" channel plays sci-fi movies all day.

This also consolidates the HDHR architecture: Maisie's emulated HDHR Prime fully
proxies the real PRIME device while adding camera channels (Protect + Bambu X1C)
and library channels, all presented to Plex as a single unified device.

Streams for library channels are generated by ffmpeg on Tokyo (HP Z620, Ubuntu,
NVIDIA GTX 1050 Ti) which has NAS media mounted at `/mnt/nas/plex-library`.

## Architecture

```
Plex / Dashboard ──→ hdhr-protect (unified HDHR emulator, port 5004)
                        ├── Channels 1-999:     proxy to real PRIME (cable)
                        ├── Channels 10001+:    go2rtc → ffmpeg (cameras)
                        └── Channels 20001+:    Tokyo ffmpeg (library content)

Stream Generation:
  hdhr-protect ──HTTP──→ Tokyo stream server (port 5050)
                            └── ffmpeg reads /mnt/nas/plex-library/{path}
                                └── outputs MPEG-TS back to caller

EPG (XMLTV):
  ├── Cable:   zap2xml (Zap2it scraper)
  ├── Cameras: self-generated 24/7 "Live" entries
  └── Library: generated schedule with episode titles + times
```

## Current State (What Exists)

- **hdhr-protect** (`packages/hdhr-protect/`) — full HDHR emulator with cable + camera support
- **PRIME proxy** — fetches real PRIME lineup, proxies cable streams via ffmpeg
- **Camera streams** — go2rtc RTSP → ffmpeg → MPEG-TS
- **SSDP advertiser** — broadcasts emulated device on LAN
- **EPG generator** — merges zap2xml + camera entries into XMLTV
- **TV page** — dashboard WebRTC playback with channel guide
- **Channel DB** — `hdhr_channels` SQLite table for camera channel config
- **Plex client** — REST API for server info, libraries, now playing, recently added
- **Maisie host** — GPU host at {LAN_IP}, NAS mounted at `/mnt/nas/plex-library`

## Channel Types

| Range       | Type    | Source                    | Stream Origin      |
|-------------|---------|---------------------------|--------------------|
| 1-999       | cable   | Real HDHR PRIME           | PRIME → ffmpeg     |
| 10001-19999 | camera  | go2rtc (Protect/X1C)     | go2rtc → ffmpeg    |
| 20001+      | library | Plex media files on NAS   | Tokyo ffmpeg       |

## Phase 1: Library Channel Data Model + API

### Goal
Define library channels in the database, expose CRUD API, build the Plex library
query capability to resolve show names to file paths.

### Database: `library_channels` table

```sql
CREATE TABLE library_channels (
  number      TEXT PRIMARY KEY,        -- e.g. "20001"
  name        TEXT NOT NULL,           -- e.g. "Golden Girls"
  mode        TEXT NOT NULL,           -- "marathon" | "shuffle" | "scheduled"
  content     TEXT NOT NULL,           -- JSON: content query config
  enabled     INTEGER NOT NULL DEFAULT 1,
  created_at  TEXT NOT NULL
);
```

**Content config examples:**

```jsonc
// Marathon: plays all episodes in order, loops, deterministic schedule
{
  "type": "show",
  "title": "The Golden Girls",
  "librarySection": "2",        // Plex library section key
  "episodeDuration": 1440       // ~24 min average, used for schedule calc
}

// Shuffle: random episodes from a show or collection
{
  "type": "show",
  "title": "Seinfeld",
  "librarySection": "2",
  "shuffle": true,
  "seed": 42                    // deterministic shuffle per day
}
```

## Phase 2: Tokyo Stream Server

### Goal
A lightweight HTTP service on Tokyo that accepts stream requests, launches ffmpeg
against local NAS files, and returns MPEG-TS.

### Service: `tokyo-streamer`

New package: `packages/tokyo-streamer/` — a small Bun/Hono app deployed to Tokyo.

```typescript
// GET /stream?file={path}&offset={seconds}
// Returns: MPEG-TS stream (video/mp2t) via ffmpeg

// GET /health
// Returns: { status: "ok", ffmpeg: true, nasMount: true }
```

**ffmpeg command for library streams:**

```bash
ffmpeg -hide_banner -loglevel warning \
  -ss {offset} \                          # seek to current position in episode
  -i "/mnt/nas/plex-library/{file}" \     # NAS-mounted media file
  -c:v copy \                              # pass-through video (already H.264/HEVC)
  -c:a aac -b:a 128k -ar 48000 -ac 2 \   # normalize audio to AAC stereo
  -f mpegts \
  -mpegts_flags +resend_headers \
  -flush_packets 1 \
  pipe:1
```

If the source is HEVC and the client needs H.264, Tokyo can transcode using NVENC:

```bash
-c:v h264_nvenc -preset p4 -cq 22 -b:v 4M
```

The current TV page uses WebRTC via go2rtc. Library channels produce MPEG-TS, so
we need an alternative player path.

**Approach**: For library channels, use an HLS proxy or direct MPEG-TS → HLS
conversion. Tokyo streamer can optionally serve HLS:


Or simpler: proxy the MPEG-TS through go2rtc by adding the Tokyo stream as a
source, then use the existing WebRTC path.

## Phase 4: Plex Integration + EPG

### Goal
Plex discovers library channels via the HDHR lineup and can tune to them with
proper guide data.

### Lineup Updates

Library channels appear in `/lineup.json`:

```json
{
  "GuideNumber": "20001",
  "GuideName": "Golden Girls",
  "URL": "http://hdhr-protect:5004/stream/library/20001"
}
```

### Stream Endpoint

`/stream/library/:number` in hdhr-protect:
1. Calls Maisie agent: "What should channel 20001 be playing right now?"
2. Agent returns `{ file, offsetSeconds, episodeTitle }`
3. hdhr-protect calls Tokyo streamer: `GET /stream?file={file}&offset={offset}`
4. Proxies MPEG-TS response to Plex

### EPG Generation

Library channels get proper XMLTV entries with calculated schedules:

```xml
<channel id="library.20001">
  <display-name>Golden Girls</display-name>
</channel>

<programme start="20260329180000 +0000" stop="20260329182400 +0000" channel="library.20001">
  <title lang="en">The Golden Girls</title>
  <sub-title lang="en">The Way We Met</sub-title>
  <desc lang="en">Season 1, Episode 25</desc>
  <category lang="en">Comedy</category>
  <episode-num system="onscreen">S01E25</episode-num>
</programme>
```

The EPG generator pre-computes 48 hours of schedule using the same deterministic
algorithm as the schedule calculator.

### Plex Setup

After lineup + EPG are ready:
1. Plex rescans the HDHR device (Settings → Live TV & DVR → Rescan)
2. New channels appear in the guide
3. Plex can tune to them and record (DVR)

## Key Technical Decisions

### Why Tokyo for stream generation?

- Media files are on the NAS, mounted via NFS on Tokyo
- Tokyo has an NVIDIA GPU for hardware transcoding if needed
- Keeps CPU-intensive ffmpeg off the Mac (which runs Maisie + go2rtc)
- Tokyo will eventually run Plex too — co-locating the streamer is natural

### Why not HLS?

- HDHR protocol expects MPEG-TS on `/auto/v{channel}`
- Plex's DVR tuner interface consumes MPEG-TS directly
- MPEG-TS is lower latency than HLS (no segment buffering)
- For dashboard playback, we route through go2rtc to get WebRTC

### Why deterministic schedules?

- No state to persist — the schedule is a pure function of time + episode list
- Multiple clients tuning at the same time see the same content (real TV feel)
- EPG can be pre-generated without tracking playback state
- Survives restarts — no "resume" logic needed

### Channel number scheme

- **1-999**: Reserved for cable (matches real PRIME channel numbers)
- **10001-19999**: Cameras (existing scheme, allows up to 9999 cameras)
- **20001-29999**: Library channels (allows up to 9999 custom channels)
